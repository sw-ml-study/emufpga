Serial candidate

SSD→RAM→expert stream→GPU state

First emulate the stream on CPU/GPU; only then substitute FPGA hardware.

  1. Pick a routed MoE quant larger than available VRAM.
  2. Fix prompt set, context, output length, concurrency, and correctness gate.
  3. Measure time-to-first-token, tokens/s, peak RAM/VRAM, bytes moved, and wall joules.
  4. Repeat across concurrency until either approach crosses over or saturates.

Decision rule written before the run

Success

Correct output within the agreed gate, model remains usable on the small GPU, and serial execution beats CPU offload in throughput or correct results/kWh at a documented concurrency.

Failure

No tested concurrency beats CPU offload, or storage/transfer/serial compute makes latency operationally useless.

Mixed

Capacity works but only for a narrow workload, hardware generation, batch size, or energy envelope. Report that boundary rather than a universal win.

FPGA comes after the crossover model. Simulate clock/bandwidth now; program hardware only when the model identifies a pipeline that could change the measured bottleneck.
